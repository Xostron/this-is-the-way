## 🗓️ ЭТАП 1: Фундамент и смена мышления (Проекты 1-3 «Школы 21»)
*Фокус: Отказ от привычек JS , освоение строгой типизации и компиляции.*

### 🛠️ Практические темы Go:
- [ ] **Синтаксис и типы:** Переменные (`var`, `:=`), явное приведение типов (забудьте про неявное сложение строк и чисел).
- [ ] **Управление потоком:** Цикл `for` (единственный в Go), `switch/case` без проваливания (no fallthrough).
- [ ] **Функции:** Возврат нескольких значений, именованные возвращаемые значения.
- [ ] **Явная обработка ошибок:** Парадигма `if err != nil` вместо `try/catch`. Деферентные вызовы (`defer`).
- [ ] **Указатели (Pointers):** Символы `*` и `&`. Передача данных в функцию по значению (копия) vs по ссылке (указатель).

### 🧠 Требования Т-Банка (Under the Hood):
- [ ] Понимание разницы между Стек (Stack) и Куча (Heap).
- [ ] Что такое Escape Analysis (анализ побега переменной в кучу) и как компилятор принимает это решение.

## 🗓️ ЭТАП 2: Структурирование данных и ООП (Проекты 4-6 «Школы 21»)
*Фокус: Архитектура приложений без классов и наследования.*

### 🛠️ Практические темы Go:
- [ ] **Массивы vs Срезы (Slices):** Создание срезов через `make()`, добавление элементов через `append()`.
- [ ] **Хеш-таблицы (Maps):** Работа с мапами, проверка существования ключа (`value, ok := m[key]`).
- [ ] **Структуры (Structs):** Аналог интерфейсов/объектов в TS. Встраивание структур (композиция вместо наследования).
- [ ] **Методы:** Функции с ресиверами (`func (p *Person) Speak()`). Понимание разницы между pointer-ресивером и value-ресивером.
- [ ] **Интерфейсы (Interfaces):** Неявная (утиная) типизация в Go. Пустой интерфейс `interface{}` (или `any` в новых версиях) и утверждение типов (Type Assertion).

### 🧠 Требования Т-Банка (Under the Hood):
- [ ] **Внутреннее устройство Slice:** Структура из трех полей (указатель на массив, `len`, `cap`). Как ведет себя `append` при превышении `cap`.
- [ ] **Внутреннее устройство Map:** Как устроен `hmap` под капотом (бакеты, хэш-функции, коллизии, эвакуация данных при росте). *Самый частый вопрос на собеседовании!*
- [ ] **Внутреннее устройство Interface:** Структуры `iface` и `eface`. Что такое таблица методов (itab). Почему `nil` интерфейс со значением `nil` не равен `nil`.

## 🗓️ ЭТАП 3: Конкурентность / Многопоточность (Продвинутые проекты)
*Фокус: Переход от однопоточного Event Loop (Node.js) к модели CSP (Communicating Sequential Processes).*

### 🛠️ Практические темы Go:
- [ ] **Горутины (Goroutines):** Ключевое слово `go`. Запуск тысяч параллельных потоков.
- [ ] **Каналы (Channels):** Передача данных между горутинами. Буферизированные и небуферизированные каналы. Закрытие каналов.
- [ ] **Оператор `select`:** Мультиплексирование каналов (работа с несколькими каналами одновременно).
- [ ] **Примитивы синхронизации (`sync`):** `sync.WaitGroup` для ожидания потоков, `sync.Mutex` и `sync.RWMutex` для предотвращения состояния гонки (Race Condition).
- [ ] **Пакет `context`:** Управление жизненным циклом запросов, отмена горутин по таймауту.

### 🧠 Требования Т-Банка (Under the Hood):
- [ ] **Планировщик Go (GMP модель):** Что такое G (Goroutine), M (Machine/OS Thread), P (Processor). Как работает Work Stealing и Syscall-блокировки.
- [ ] **Сборщик мусора (Garbage Collector):** Трёхцветный алгоритм маркировки и очистки (Mark and Sweep), Write Barrier. Как GC влияет на задержки (Stop The World).
- [ ] **Инструменты:** Умение пользоваться `go test -race` для поиска состояний гонки.

## 🗓️ ЭТАП 4: Промышленная разработка и Стек Т-Банка (Осень 2026 — Январь 2027)
*Фокус: Написание реального микросервиса по стандартам финтеха.*

### 🛠️ Инструменты и Архитектура:
- [ ] **Управление зависимостями:** Использование `go mod` (стандарт после упразднения GOPATH).
- [ ] **Веб-сервер:** Стандартный пакет `net/http` (фреймворки вроде Gin/Fiber изучить поверхностно, Т-Банк ценит знание базы).
- [ ] **Работа с БД:** PostgreSQL + драйвер `pgx` или надстройка `sqlx`. Использование генератора кода `sqlc` или ORM `GORM`.
- [ ] **Протоколы:** Уверенное владение REST API и **gRPC + Protocol Buffers** (микросервисный стандарт Т-Банка).
- [ ] **Брокеры сообщений:** Базовое понимание работы Apache Kafka или RabbitMQ.
- [ ] **Архитектурные паттерны:** Чистая архитектура (Clean Architecture) / Гексагональная архитектура. Разделение на слои: Handler -> Usecase -> Repository.
